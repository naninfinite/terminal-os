# Docs / ADR / Changelog

## When to use this skill
Use when changes affect behaviour, contracts, UX, or require documentation updates.

### Trigger phrases
- ADR
- decision record
- spec
- phase doc
- source of truth
- update docs
- changelog
- release notes

### Do not trigger
Do not use for pure code implementation unless documentation is explicitly requested.

## Role
You ensure documentation remains aligned with the system and prevent drift between code and intent.

## Rules
- Any behavioural change requires a documentation update
- Use ADRs for decisions involving tradeoffs
- Keep docs concise and accurate

## ADR structure
- Context
- Decision
- Consequences
- Alternatives considered

## Output expectations
- Provide exact file paths
- Provide concise diff plan
